# Question-duplicate pilot (offline stage)

Labeled question pairs and an offline check for a future duplicate-detection pilot. This stage
**makes no TypeSafe or network calls** and does not touch the database, seed, routes, competition
logic or any money flow. It reads only `pairs.json` and, read-only, `packages/database/prisma/seed.ts`.

## Labels

| Label                | Meaning                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `duplicate_question` | Same fact, same correct answer, reworded. One makes the other redundant.                     |
| `answer_leakage`     | Different question, but its wording or correct answer gives away the other's answer.         |
| `related_distinct`   | Same topic or template, different fact and answer. A hard negative that must not be flagged. |
| `seed_variant`       | Intentional `(set N)` copy generated by `seed.ts`. Expected by design, reported separately.  |

`pairs.json` has 130 pool questions (20 verbatim from `seed.ts`, the rest hand-written test data that
is never loaded anywhere) and 88 pairs. In each pair, `candidate` plays the new question and
`existing` plays the one already in the bank. Every pair has a `split`:

| Split     | Pairs (dup / leak / related / seed) | Status                                                                                                  |
| --------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `dev`     | 20 / 16 / 25 / 12                   | Used while building the shortlist. Results here are post-hoc.                                           |
| `holdout` | 4 / 4 / 4 / 3                       | Written after the answer-in-text rule and its guards were fixed, and not consulted while choosing them. |

## Run the offline checks

From the repo root (Node 20+, no install needed):

```sh
node --test tools/question-dedup-pilot/evaluate.test.mjs        # unit tests + data validation
node tools/question-dedup-pilot/evaluate.mjs                     # validate + shortlist recall
node tools/question-dedup-pilot/evaluate.mjs --misses            # also list positives outside top K
node tools/question-dedup-pilot/evaluate.mjs --k 5,10,20 --json  # machine-readable
node tools/question-dedup-pilot/evaluate.mjs --min-recall 0.95   # exit 1 if any positive label is below 0.95 at max K
```

Exit codes: `0` ok, `1` recall gate failed, `2` validation failed.

## What "shortlist recall" measures

Only shortlisted pairs would ever be sent to TypeSafe, so a partner the shortlist misses can never be
judged. For each candidate, every other pool question is scored by a cheap local similarity (stem-word
overlap, choice overlap, same correct answer) and the top K are kept. Recall is the share of labeled
partners found in that top K.

- Recall is reported separately for `duplicate_question`, `answer_leakage` and `seed_variant`, and
  separately for `dev` and `holdout`. There is deliberately no blended overall number.
- `related_distinct` is shown for context only: surfacing it is useful (TypeSafe must reject it), but a
  miss costs nothing.
- Unlabeled pool pairs are assumed distinct, so this stage cannot measure precision. That needs the
  TypeSafe judgments.

### Answer-in-text signal

The shortlist score adds `0.3` when either question's correct answer appears, as a whole-token run,
in the other question's text (the stem only, not the choices). It targets leakage such as "What is
9 squared?" against "What is the square root of 81?", where the answers are in each other's stems but
the wording barely overlaps.

Guards keep short or generic answers from matching everything. An answer is ignored if it is a single
character or single digit, or if it appears in the stems of more than 5% of the pool (minimum 3). Matching
is by whole tokens, so `12` never matches `120`. The parameters (`0.3`, 2 characters, 5%) were fixed
before running the numbers and were not swept.

The report includes an ablation (signal off, on, and on without guards) and counts how often the signal
fires across all pool pairs. Fires on unlabeled pairs are listed for hand review: some are real relations
nobody labeled, others are false matches the guards do not stop (for example the answer "Africa"
matching the stem "Which ocean lies east of Africa?").

## Caveats before trusting the numbers

- The set is small and hand-written, so treat recall as a smoke test, not a benchmark. Paraphrases
  written by one author tend to reuse words, which flatters a word-overlap shortlist.
- **`dev` is not independent validation.** The answer-in-text rule was added because `dev` pairs p027 and
  p028 were missed. Finding them now is a regression check, not evidence the rule generalizes.
- **`holdout` is weak evidence.** It was written after the rule was fixed, but by the same author who
  knew the rule, and each label has only 3 or 4 pairs, so one pair moves a percentage by 25 points.
- The signal only helps when an answer literally appears in a question. Relations with no shared text
  (same answer via unrelated facts, for example "Rio de Janeiro" against "2016 Olympics") still depend
  on the other score components.
- Any further tuning against these pairs should use a fresh holdout; do not reuse `holdout` once it has
  informed a change.
